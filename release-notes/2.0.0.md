## AE2 Web Integration 2.0.0

A redesigned web interface, live storage and CPU views, resource history and a personal dashboard.
These are the changes since **1.2.0-pre** across GTNH 1.7.10, AE2 UEL 1.12.2, Forge 1.20.1 and
NeoForge 1.21.1. The main mod remains server-side.

### New web interface

- Responsive desktop and mobile layouts, including redesigned login and registration.
- Light, dark and system appearance; **Monocraft or Lato** fonts.
- Names, icons or both, with configurable columns and page size, including no pagination.
- Resource details, context menus, custom tooltips and remembered display preferences.
- Colored, dismissible notifications for actions and errors.

### Live terminal and CPU views

- **SSE updates** for storage and selected CPUs, with connection status and automatic recovery.
- Incremental tile updates and delayed automatic reordering keep changing lists easier to use.
- Live resource quantities, crafting times and production-rate estimates where tracking is available.
- Busy CPU output previews and player/automation selection indicators, including supported AdvancedAE CPUs.
- Optional automatic updates: CPU lists refresh periodically; selected CPU details stream live.

### Resource tracking

- Independent stock and flow tracking, with input, output, net flow and transfer-operation statistics.
- Two-minute flow summaries and one-hour sampled stock changes in tooltips and resource details.
- Interactive charts with zoom, point selection, series toggles and pixel/smooth styles.
- Sampled stock steps, grouped flow bars and explicit gaps for missing measurements.
- Per-network sampling and retention within administrator limits. Defaults: five-minute stock,
  one-minute flow and seven-day retention, also bounded by record limits.

### Pins and Home

- Account-owned terminal pins stay above search and filters, with independent ordering per network.
- **Home cards** combine pinned resources from multiple networks, with configurable charts and summaries.
- Pins keep access to recorded history when resources disappear from storage.

### Crafting

- Clearer plans and CPU layouts for missing ingredients, storage requirements and resource states.
- **PNG plan export** with configurable layout, ordering, contents and background.
- Persistent completed/cancelled job history, including resource timings, totals and provider details.
- Requester attribution for players, automation and web orders, including merged jobs.
- Per-network machine-crafting tracking and history retention.
- Lite crafting, ignore-missing, pause and selection controls where supported by the installed AE2 version.

### Icons and themes

- Optional **item and fluid icons** exported from your modpack and resource packs.
- A standalone client icon generator for every supported Minecraft version; server packs use `.ae2wi-icons`.
- Server-installed **ZIP themes**, an administrator-selected default, per-browser choice and safe-mode recovery.
- A documented TypeScript theme API, shared data/actions, optional helpers and a complete example project.

### Login and administration

- **Remember me** survives server restarts; active use renews sessions within their lifetime limits.
- **Server Settings** edits supported options with validation and live application.
- Sensitive settings remain file-only; administrators can disable the web settings editor.
- Write-only notification credentials with explicit keep, replace and clear controls.

### Notifications

- Discord crafting cards, compact item thumbnails or plain-text notifications.
- Network names and requester attribution in Discord and ntfy notifications.
- Notification configuration through Server Settings; existing private-mode restrictions still apply.

### Reliability and API

- World-local **SQLite storage** for grid settings, histories and pins; existing grid-identity JSON is
  imported once and archived as `.old`.
- Improved stream cleanup, reconnect behavior and live updates for resources without stable keys.
- Improved background persistence, history-write recovery and network failure isolation.
- Fixed legacy configuration import on GTNH/UEL and stock readings for UEL void storage.
- TypeScript frontend, build-time HTTP bindings and expanded OpenAPI documentation.

**API compatibility:** response fields now use `displayName`, `registryNamespace`, `registryPath`,
`jobId` and `dimensionId`. External integrations must use the 2.0 schema; old field aliases are not retained.
