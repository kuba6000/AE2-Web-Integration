## AE2 Web Integration 2.0.0

Your ME network now has a live web terminal, resource history and a personal dashboard. Version 2.0
rebuilds the web interface for desktop and mobile, adds item icons and custom themes, and keeps
stock, flow and completed crafting history available after a server restart.

This release brings the following changes since **1.2.0-pre** to the supported GTNH 1.7.10,
AE2 UEL 1.12.2, Forge 1.20.1 and NeoForge 1.21.1 versions. The main mod remains server-side;
players do not need a client mod to use the web interface.

### A new web terminal

- A Minecraft-inspired interface with responsive navigation, desktop side panels and layouts designed
  for phones, including redesigned login and registration screens.
- Light, dark and system appearance options, with a choice of **Monocraft or Lato**. The login screen
  also has its own remembered light/dark toggle.
- Display resources as names, icons and names, or icons only. Adjust the grid columns and choose
  50, 100, 250, 500 or 1,000 resources per page, or disable pagination. The default is 500.
- Resource details, context menus and consistent custom tooltips bring identity, quantities and
  tracking information together. Browser display preferences are remembered.
- Colored, dismissible notifications report actions and API errors without shifting the page layout.

### Live storage and crafting views

- The storage terminal and selected crafting CPU now receive live updates through **Server-Sent
  Events (SSE)**, with a connection indicator and automatic recovery when a stream is interrupted.
- Resource tiles update incrementally. Automatic reordering is delayed to keep the terminal usable
  while quantities change; changing search or sorting still takes effect immediately.
- CPU views show changing stored, active and pending quantities, with timing and production-rate
  estimates updating between server messages where tracking information is available.
- Busy CPU selectors show the crafted resource. Selection-mode indicators distinguish processors
  reserved for players, automation or both where supported by AE2.
- Live CPU support includes supported AdvancedAE processors on modern Minecraft versions.
- With **Automatic updates** enabled, the CPU overview uses periodic refreshes; live streaming applies
  to the selected CPU view. Turn automatic updates off to use manual refresh instead.

### Resource history: stock, input, output and net flow

- Track stored quantities and resource flow independently for each network. Flow measures accepted
  transfers; it can change even when the stored quantity stays the same.
- Tooltips and resource details include recent two-minute flow summaries and one-hour sampled stock
  changes when the corresponding tracking is enabled. Flow also includes transfer-operation counts
  and rates.
- Open a dedicated resource-history view with stock, input, output and net-flow charts. Zoom into a
  period, toggle individual series, or select a point with a click or tap to keep its values visible.
- Stock uses a stepped line with actual sample points. Flow bars cover their measurement intervals
  and can be grouped for readability; chart appearance offers pixel and smooth styles.
- Choose stock sampling, flow recording intervals and retention separately for each network,
  within administrator-defined limits. Missing measurements remain gaps instead of becoming zeroes.
- Defaults are five-minute stock samples, one-minute persisted flow intervals and seven-day retention.
  Record limits also apply and can shorten the retained history on busy networks.

### Personal pins and a Home dashboard

- Pin resources above the terminal's normal results, independently of search and filters. Pins occupy
  complete rows, adapt to the grid width and keep their own order for each network.
- Pin resources to **Home** to monitor several networks together, regardless of which network is
  currently selected.
- Configure each Home card's chart, historical flow period, recent flow summary and displayed values.
- Pins belong to the account. Other players using the same network keep their own selections.
- A pinned resource can retain access to its recorded history after it disappears from storage.

### Crafting plans and lasting crafting history

- Reworked plan and CPU layouts make missing ingredients, storage requirements, resource states and
  supported crafting-step counts easier to inspect. Busy processors also show their output in the
  plan's CPU selector.
- Export a calculated plan as a **PNG image**. Choose its rows, columns, ordering, displayed quantities,
  names, icons and background. The export includes the full plan independently of the current search
  or browser size, and also works without an icon pack.
- Completed and cancelled jobs are stored persistently, with resource timings, production totals,
  provider information and locations where available.
- Crafting history records who requested a job: players, automation or the web interface. Merged
  orders retain their requester attribution. Requesters also appear in live CPU views and notifications.
- Control machine-requested crafting tracking and crafting-history retention per network. The default
  retention is seven days, subject to the configured job limit.
- Native options such as Lite crafting, ignoring missing ingredients, CPU pause and selection modes
  are exposed according to the capabilities of the installed AE2 version.

### Icons from your modpack, themes of your choice

- A separate **client icon generator** is available for each supported Minecraft version. Export
  item and fluid icons using your actual modpack and resource packs, then install the resulting
  `.ae2wi-icons` archive on the server.
- Icon packs are optional. The terminal remains usable with resource names when no pack is installed.
  Archives are discovered by extension, so their generated filenames can be kept.
- Administrators can install **ZIP themes**, choose a server default, and let each browser follow that
  default or select another theme. A built-in safe mode provides a way back if a theme cannot be used.
- Theme authors get a documented TypeScript contract, shared application data and actions, optional
  helpers, compatibility declarations and a complete example project. Themes control their own layout
  and presentation.

### Login and administration

- **Remember me** now survives server restarts. Active use, including watching live views, extends
  the session's idle timeout within its maximum lifetime. Logout and credential changes revoke sessions.
- Administrators can edit supported configuration options from **Server Settings**, with grouped
  controls, validation and detection of settings changed since the form was loaded.
- Supported changes can be saved and applied without restarting the web listener. Sensitive options
  such as the port, admin password and public mode remain file-only; web settings access can be disabled.
- Notification credentials are write-only, with explicit options to keep, replace or clear them.

### Richer crafting notifications

- Discord notifications offer a rendered crafting card, a compact item-thumbnail style or plain text.
- Cards include the crafted resource, network, CPU, duration and requesters, with icon and text fallbacks.
- Discord and ntfy notifications use configured network names and include requester attribution.
- Notification options are available in the administrator's web settings. Existing private-mode
  restrictions still apply.

### Reliability and integration

- Grid identities and settings, resource history, crafting history and pins share a world-local
  SQLite database. Existing released grid-identity JSON data is imported once and archived as `.old`.
- Improved stream cleanup and subscription replacement prevent abandoned tabs and repeated refreshes
  from occupying live-terminal slots indefinitely.
- Reconnecting views retain their content during recovery, and anonymous resources remain visible
  through live updates even when no stable resource key is available.
- Improved history-write recovery, bounded background persistence and cleanup, and isolation of
  failures affecting individual networks.
- Corrected legacy configuration import on GTNH and UEL, and stock readings for UEL storage that
  accepts resources without retaining them.
- The web frontend is written in TypeScript, and HTTP request bindings are generated at build time.
  OpenAPI documentation covers the expanded API for live views, history, pins, themes and settings.

**For API integrations:** resource responses now use `displayName`, `registryNamespace` and
`registryPath` in place of the old name/combined-ID fields. Other renamed fields include `jobId`
and `dimensionId`; resource metadata also includes type, component count and damage where available.
Update external clients against the 2.0 API schema; legacy field aliases are not retained.
